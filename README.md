# ViaTradeBackend

Серверная инвестиционная платформа для автоматизированного анализа финансовых инструментов, формирования торговых сигналов и доставки уведомлений пользователям.

Проект разработан в рамках дипломной работы по специальности **09.02.07 «Информационные системы и программирование»**.

## Назначение системы

Платформа предназначена для автоматизации процесса анализа рыночных данных и формирования инвестиционных сигналов на основе заранее настроенных торговых стратегий.

Система позволяет:

* хранить пользовательские данные;
* управлять инвестиционными стратегиями;
* назначать стратегии на финансовые инструменты;
* получать результаты аналитической обработки;
* формировать сигналы на вход в позицию;
* вести статистику эффективности стратегий;
* отправлять уведомления через Telegram.


## Архитектура решения

Проект состоит из нескольких независимых компонентов.
- ViaTradeBackend (этот репозиторий)
- PythonAnalyzer (https://github.com/mrRiten/ViaTradeAnalyzer)
- PythonTgBot (https://github.com/mrRiten/ViaTradeTgBot)

### Основной Backend

Основное приложение реализовано на ASP.NET Core 10 и отвечает за:

* авторизацию пользователей;
* управление сессиями;
* хранение данных;
* работу со стратегиями;
* управление подписками;
* обработку сигналов;
* взаимодействие с внешними сервисами.

### Аналитический модуль

Отдельный Python-сервис выполняет:

* загрузку рыночных данных;
* расчёт аналитических показателей;
* обработку финансовых инструментов;
* подготовку статистики;
* экспорт результатов в CSV.

Обмен данными между аналитическим модулем и Backend осуществляется через файловое взаимодействие.

### Telegram Bot

Отдельный сервис уведомлений принимает запросы от Backend и выполняет отправку сообщений пользователям через Telegram Bot API.

Для взаимодействия используются защищённые системные маршруты и сервисные ключи доступа.

### Напоминания со ссылкой на инструмент

`TelegramReminderPublisherService` публикует напоминания через Redis Stream:
`notification_id`, `type`, `user_id`, `chat_id`, `payload`, `created_at`.
В JSON `payload` передаётся `instrumentId` из существующей проекции инструмента:

```json
{"reminderId":42,"text":"Buy","remindAt":"2026-10-11T12:00:00Z","instrumentTicker":"AAPL","instrumentId":123}
```

Поле — положительный int32; при отсутствующей проекции публикуется `null`.
Это аддитивное расширение schemaVersion 1: старые payload остаются совместимыми,
новые не меняют notification ID, формат Stream или HTTP API. Миграция БД не требуется.
Контракт описан в `docs/notification-stream.asyncapi.yaml` репозитория ViaTrade-TgBot.

Публичный URL не передаётся через Stream и не настраивается в backend. Бот строит
`/stocks/{instrumentId}` из своей настройки `VIATRADE_WEB_BASE_URL`, сохраняя префикс пути,
и делает тикер в напоминании кликабельным. Первая строка — «Напоминание: AAPL»,
ниже курсивом — запланированная дата и время из `remindAt` в МСК (UTC+3),
затем — текст без пустых разделителей. Это время, заданное для напоминания,
а не время публикации или подтверждения доставки. Исходный часовой пояс пользователя
не хранится; бот показывает тот же момент в МСК. Без смайликов
и inline-кнопок. Метка и тикер выделены жирным; пробелы и переносы внутри текста
сохраняются, а повторные пробельные символы в тикере заменяются одиночными пробелами.
При отсутствии адреса сайта или ID тикер остаётся обычным текстом; без тикера подпись
ссылки — «Инструмент». Включение: обновить бот, затем
backend, затем настроить доступный адрес сайта в боте. Уже отправленные сообщения
автоматически не меняются. Переход сохраняет авторизацию/PIN сайта; `DeliveredAt`
по-прежнему подтверждает отправку в Telegram, а не клик или выполнение задачи.
Публикация по-прежнему предшествует `MarkReminderPublishedCommand`.

Проверки без MySQL, Redis и Telegram:

```powershell
dotnet build ViaTradeBackend.sln
dotnet test Tests/ViaTrade.Tests.csproj --no-build --filter FullyQualifiedName~TelegramReminderPublisherTests
```

Тесты запускают настоящий hosted publisher с контролируемым ISender и настоящий
Redis-адаптер с подменой IDatabase, проверяют ID, camelCase, шесть Stream-полей,
порядок публикации и обработки сбоя. Успешный тест сохраняет фактически опубликованную
запись в `Tests/bin/Debug/net10.0/reminder-stream-entry.json` для проверки Python-моделью
бота. Реальный переход по тикеру проверяется отдельно с тестовым Telegram-аккаунтом
и доступным сайтом, включая авторизацию и PIN.

## Запуск проекта	

### Требования

* .NET 10 SDK
* MySQLServer
* Python 3.11+
* Git
* Redis

### Backend

```bash
git clone https://github.com/ViaCode-Team/ViaTradeBackend.git
dotnet restore
dotnet ef database update
dotnet run
```

### Analyzer

```bash
git clone https://github.com/mrRiten/ViaTradeAnalyzer
uv sync
python main.py
```
*Анализатор автоматичеки создаст нужные файлы и дериктории для хранения данных парсинга и анализа*

### Telegram Bot

```bash
git clone https://github.com/mrRiten/ViaTradeTgBot
uv sync
python main.py
```
*В конфигурации бота необходимо прописать токен авторизации сервиса, совпадающий с токеном оснвного бэкенда*

## Результат проекта

В рамках проекта была реализована серверная инвестиционная платформа, объединяющая возможности хранения данных, аналитической обработки рыночной информации и автоматической доставки торговых сигналов пользователям.

Архитектура решения позволяет независимо развивать аналитические сервисы, масштабировать серверную часть и подключать дополнительные каналы уведомлений без изменения основных бизнес-процессов системы.
